## 复现

根目录运行（使用本机已有依赖与独立测试库）：

- ./scripts/backend.ps1 test
- node --test scripts/frontend-rules.test.mjs
- ./scripts/verify-single.ps1 -Advanced
- npm --prefix frontend run build

verify-single.ps1 先使用已有专用 PostgreSQL，再创建带日期与随机后缀的新测试数据库；不重置正式库。测试 API 固定 8083/8084，对应浏览器来源 5175/5176。Node 测试客户端拒绝正式端口 8082。脚本默认关闭自己创建的进程；KeepRunning 仅供进一步 UI 检查，并将进程身份记录在 .local/test-servers.json。脚本恢复调用者的相关环境变量。

## 双实例集成的 11 组

1. 干净首次启动：没有赛事和默认演示人员，普通注册尚未开放。
2. 两个同时初始化请求只成功一次；初始化后不能再次建立主办；跨部署 Cookie 无效。
3. 并发创建只绑定一场赛事，后续创建 409；草稿匿名不可读；旧版本、缺 CSRF、旧显示序号有对应守卫。
4. 服务端导出只有外观、图池、规则、文案与格式版本，不带主办身份或任何运行记录。
5. 范式示例可选载入；虚构人员单独显式载入且不能重复；从 A 导出并在 B 配置后，两个实例的规则、图池、外观、用户和报名各自独立。
6. 发布后 GET /instance 只公开当前赛事；普通注册、报名、重复拦截、审核与主办权限继续可用。
7. 完整海选尝试、精确到 0.0001 的排名及私有证据隔离正确。
8. 非行动方和同版本并发 BP 被拒绝；随机结果与实际演奏槽持久化。
9. 待审阻断结算、真实同分加赛、冠军确认、归档和历史保留；A 结束不改变 B 的进度。
10. 主办方以本人参赛身份交分，仍然不能审核自己的成绩。
11. 退出登录作废服务端会话，并清除同一路径的 Cookie。

规则冻结版本在生成对阵、结算和归档后保持原值；乐观锁版本单独递增。每个 3/5/8 人场景使用新的独立实例数据库，实际完成每场 BP、双方交分、裁判审核与晋级，不复用一个多赛事数据库来冒充部署隔离。

## 早期界面验证记录（本轮结果见末节）

独立 UI 数据库中实际创建测试主办，选择范式预设，保存 18 谱草稿，校验并发布；浏览器自动进入 /，显示当前比赛与新导航。重启 API 后仍能读取已发布配置；登录并刷新后退出，主办入口和个人信息立即清除。公开规则页将演奏顺序显示为行动方与选曲步骤，不展示内部槽编号。正式默认 5174 页面保持准备状态，不替使用者设置管理密码。截图位于 docs/screenshots/single-event.png。

根目录 Start.cmd 实际完成构建、数据库与前后端启动；重复执行不会新增进程。Stop.cmd 能关闭跟踪的进程并保留数据。旧版 rhythm_area 中原有的 3 条赛事记录仍在，未迁入新的单赛事默认库。

上述能力已在 v0.3 扩展场景验证；任意资格图、瑞士轮与外部官方账号同步仍不在支持范围。初次运行还依赖本机已有工具和联网安装缺失依赖；没有声称在全新无工具的电脑上直接免安装运行。

## v0.3 扩展验收

赛制纯函数逐一遍历 2–256 人：单败全员唯一落位、恰好 N−1 场实际赛；双败胜败来源图无未决悬空、reset 规则另有实际接口场景；循环恰好 N(N−1)/2 场、每对一次、同轮无重复出场。

| 实际数据库场景 | 结果 |
| --- | --- |
| 双败 3、5、8 人，败者组赢第一场总决赛 | 5、9、15 场实际比赛，均触发 reset 后确认冠军 |
| 3、5 人循环 | 3、10 场实际比赛并确认名次 |
| 5 人循环取前 4 再单败 | 10 + 3 场实际比赛，两个阶段分别持久化 |
| 3 人循环三方同胜负取前 2 | 晋级暂停；同名次排序记录附加赛依据后推进，最终完成 4 场 |
| 3 人双败一曲胜优势 | 总决赛按 A 方已有 1 曲胜提前确认，共 4 场 |
| 3 人先胜 | 两曲达标后不需给第三曲填 0；提交故障前成绩、申诉、范围裁判受理重赛，旧成绩 superseded 后不再计入 |
| 3 人密封 / 删除已选 | 无关用户读不到密封选择与候选变化；删曲后实际槽减少且双方按真实槽提交 |
| 3 队与 2 队团队海选 | 真实建队、成员加入、唯一性、冻结、逐曲阵容、成员分数聚合；本队成员裁判不能自审 |
| 2 人海选同分 | 未完成海选不能跳过；有依据的同分排序生成正赛，保留正式榜快照 |
| 截止窗口 | 截止后报名被服务端拒绝 |
| 3 人固定曲 / 神秘随机 | 无 BP 固定曲可实际演奏；神秘图池与候选揭晓前不泄漏原元数据，抽取后等待明确揭晓，揭晓后公开 |

共 18 个不同扩展场景，均使用新的独立数据库。最终额外重跑固定曲、神秘曲与 3 人双败，验证私有候选和场次 ID 兼容修改。API 集成客户端拒绝正式端口；正式默认实例没有被录屏账号占用。
