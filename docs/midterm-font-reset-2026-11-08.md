# 统一字号、单场重置与独立实例

本轮在期中作业副本完成，未修改 HW2；已有赛事、账号、队伍、谱面及赛果均保留。

## 字号

以图池工作台为基准，所有分页面共享正文 16px、辅助信息 14px、卡片标题 18px、区域标题 24px、手机页标题 30px / 桌面页标题 36px。曲库原有额外放大的标题和输入字也已对齐。大字号统一放大 25%，无需逐页另行设置。倒计时和比分保留数字展示层级。

移除了旧页面另一套像素字号，将 44 个旧字号变量映射到相同层级。页面排版继续使用 Tailwind；全局只提供设计变量与基础文档样式。

## 单场重置

主办登录后，比赛室标题右侧显示“重置比赛”，普通对局及多人同曲晋级轮均支持。填写原因并确认后：

- 普通比赛清空当前 BP、逐曲阵容、交分与加赛，清除胜者；比赛代次增加，回到第一项 BP 等待开赛。固定曲比赛重建原有曲序，回到第一首等待开赛。
- 旧成绩与成员成绩保留并标记 superseded，选禁 / 曲序 / 阵容快照保存在 match_history，赛务决定留在审计中。多人晋级轮保留同一套公平曲目，将原名次留在重置审计快照中。
- 倒计时回到初始状态，必须再次点击开赛；旧的比赛 / 计时版本不能继续操作。
- 未开始的依赖场次回到等待来源。后续已开赛、已有选禁或交分，或后续阶段已经生成时，阻止上游重置并给出明确原因。历史赛程与归档记录保持只读。
- 双败总决赛 F1 重置后，未开始的 F2 留作历史；如再次触发双败重赛决赛，生成新的独立场次，避免重复编号。

仅主办可调用两个新增 reset 接口，裁判仍可使用原来的有记录重赛 / 改判功能。新接口拥有独立的后端权限、原因及版本校验，具体见 [API 说明](api.md)。本轮共 84 个 API，数据库迁移仍为 11。

## 验证

后端 52 项、前端与预设 47 项测试通过，前端类型检查和生产构建通过。原有 83 项集成流程完整通过；新增 6 项重置专项分别覆盖个人、团队、固定曲、个人 / 团队同曲晋级轮和双败重赛决赛，共 89 项集成流程。结构检查通过。

浏览器已核对图池、曲库、规则、看板与比赛室字号，并实际完成开赛、一次 BP 与主办重置，确认回到第一项 BP、完整 60 秒及等待开赛。访客看不到重置按钮。团队赛公开比分为 6,000,000 对 5,982,000，对应逐曲两人成绩相加。
