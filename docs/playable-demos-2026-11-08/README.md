# 个人赛与团队赛实例

双击项目根目录 `启动个人赛实例.cmd` 或 `启动团队赛实例.cmd`。再次启动只保留当前进度，不重建赛事。两个实例、原有三分钟展示实例与 HW2 的数据库均独立。

| 实例 | 看板 | 规模 |
| --- | --- | --- |
| 个人赛 | http://127.0.0.1:5196/schedule | 8 人，单败冠军赛 |
| 团队赛 | http://127.0.0.1:5198/schedule | 8 队，每队 2 人，每首 2 人成绩相加 |

使用 [实例导航.html](实例导航.html) 打开待开赛 BP、交分中、已完成、图池与曲库。每个实例均有 24 张带曲绘的范式：起源谱面，18 张比赛曲、6 张加赛曲；每次 BP 60 秒，每首交分 4 分钟。团队实例还保留组队大厅及逐曲阵容。

两个实例的主办账号均为 **demo-host**，密码均为 **Demo-host-2026!**，账号只属于各自实例。

| 身份 | 个人赛账号 | 团队赛账号 | 密码 |
| --- | --- | --- | --- |
| 待开赛 BP 的 A 方 | solo-player-02（白羽） | team-captain-02（回声边界） | Demo-player-2026! |
| 待开赛 BP 的 B 方 | solo-player-07（空镜） | team-captain-07（极光轨迹） | Demo-player-2026! |
| 其他选手 / 队长 | solo-player-01 至 08 | team-captain-01 至 08 | Demo-player-2026! |
| 队员 | — | team-member-01 至 08 | Demo-player-2026! |

检查流程：主办登录 → 赛事看板 → 当前阶段 → 待开赛比赛室 → 开赛 → 点曲绘并确认 → 重置比赛 → 确认重置 → 回到第一步 BP 与完整 60 秒。另可打开交分中场次检查已审首曲和暂停状态，打开已完成场次检查比分与胜者。团队赛使用队长账号进行 BP 和阵容操作；普通队员不能代替队长选禁。

“重置比赛”位于比赛室标题右侧，仅主办可操作，必须填写原因。已选曲、阵容、交分和倒计时重新开始，往次成绩标为已替代并保留；需要重新点击开赛。无 BP 的固定曲比赛直接回到第一首等待开赛。后续已开赛、已有选禁/交分，或后续阶段已生成时，服务器会阻止上游重置并给出原因；历史赛程与归档记录保持只读。

`solo.json` / `team.json` 保存首次准备时的页面入口和虚构账号；赛程与分数以后端当前状态为准。`solo-template.json` / `team-template.json` 是不含人员、报名、交分和会话的配置预设，可用于另一份空白部署。
