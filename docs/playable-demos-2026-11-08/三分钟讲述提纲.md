# 三分钟展示提纲：个人赛主流程，团队赛补充

目标 175 秒，预留 5 秒。先打开两个实例并登录主办：demo-host / Demo-host-2026!。提前从“实例导航.html”打开规则、曲库、图池、待开赛比赛、已完成比赛和团队赛页面。

| 时间 | 展示页面与操作 | 大致讲述内容 |
| --- | --- | --- |
| 0:00–0:15 | 个人赛首页 | 在第二次作业的基础上，我完善了律竞音游赛事系统。前端使用 React，后端使用 Scala，数据保存到 PostgreSQL，覆盖赛事配置、报名、选禁、交分和晋级。 |
| 0:15–0:40 | 赛事规则 / 配置 | 一份部署运行一场比赛，主办可以配置个人或团队、各阶段赛制、计分和图池。系统支持排名赛、单败、双败和循环赛。开赛后也能调整规则，保留已完成记录、重排未完成赛程。这里只简述支持范围，不逐项切换赛制。 |
| 0:40–1:05 | 曲库 → 图池工作台 | 曲库导入和赛事分池分开。曲库只需要基础谱面信息，可使用预设并导入曲绘；图池工作台通过搜索、排序和批量选择组织比赛用曲。难度色边框方便辨认。 |
| 1:05–1:55 | 赛事看板 → 待开赛比赛室；开赛、选一张并确认、立即暂停，最后展示重置 | 赛程按阶段展示，点击对阵进入比赛室。BP 每页五列两行；每次选禁六十秒，每首交分四分钟，由后端检查状态和权限。裁判可以暂停；主办可以重置本场，旧记录保留。若现场展示重置，确认后回到第一项 BP 与完整六十秒。 |
| 1:55–2:25 | 已完成比赛；可切到交分中场次 | 这里是一场已完成的样例。成绩通过审核后进入比分区，裁判确认赛果后推进晋级。已审成绩、曲目、胜者和历史记录可以回看。交分中样例保留暂停状态，刷新后进度仍在。 |
| 2:25–2:50 | 团队赛参赛者 / 组队大厅 → 已完成比赛 | 团队实例有八支双人队伍。团队容量按队伍计算，队长负责选禁和逐曲阵容；本场每首两人成绩相加。系统还支持队长认定、自由组队和队长选人等组织方式，本次不展开演示全部方式。 |
| 2:50–2:55 | 停留在团队比分或赛事看板 | 这次完善了赛事操作的完整流程，并将页面操作与后端权限、审核和持久化连接起来。 |

讲述重点：比赛能从配置走到赛果；曲库与分池操作方便；比赛操作有权限与计时；个人和团队使用同一套可配置系统。

实际演示优先保证“开赛—图形 BP—暂停”完成；接近三分钟时，重置只指一下按钮即可，团队只讲人数、队长和计分差异。不要等待整轮 BP 或四分钟计时结束，也不用逐条介绍所有配置项。

页面入口：个人赛 http://127.0.0.1:5196/ ，团队赛 http://127.0.0.1:5198/ 。再次失效时，双击项目根目录的“启动个人赛实例.cmd”和“启动团队赛实例.cmd”，保留已有进度。
