# 比赛室：现场、逐人交分与审核

本轮在期中作业副本完成。

## 页面结构

比赛室使用纵向排列。顶部依次为 BP 记录和演奏曲目，曲绘缩小为五列，保留对应游戏难度色边框，禁曲叠加 BAN 图标与文字。原独立 BP 记录页移除，旧链接自动返回比赛室。

中间为当前实况和倒计时。A 方分数在左，曲绘、曲名在中间，B 方分数在右；团队赛在每方总分下显示逐位成员已审核成绩。尚未审核的交分不会改变公开比分。

下方依次为成绩提交、本人的交分记录、裁判待审列表和赛果结算。审核与结算不再放在侧栏。原有重赛、改判与申诉入口保留在“赛务处理”中。

## 在哪里交分

比赛室顶部有“交分”按钮，点击直达本页表单。个人赛由本场选手提交；团队赛由队长选定逐曲阵容、录入每位出场队员成绩，后端依规则求和或平均。已保存阵容后，成员分数输入优先显示。

主办 / 裁判视角显示双方交分状态和“切换参赛账号交分”入口。登录后自动回到本场交分位置。普通队员可查看，由队长统一提交。

开赛后当前曲计时运行时可提交；暂停、超时和等待开赛时仍显示交分区域及状态。裁判在页面底部逐人核对后通过或驳回，审核完成才更新实况。

## 接口与记录

`GET /matches/:id/scores` 的每条曲目比分增加 `aMembers` / `bMembers`，成员字段为 `userId`、`displayName`、`value`。仅返回当前比赛代次、每方该曲最新一份已审核成绩的成员，待审、驳回及重置前的旧成绩不公开。

仍为 84 个 API、数据库迁移 11，无新增接口或迁移。切换账号时清除旧账号的页面缓存。

## 验证

Scala 52 项、前端与曲库预设 47 项、89 项集成流程通过；前端类型检查、生产构建及课程结构检查通过。团队专项检查覆盖待审 / 驳回不公开、审核后逐人成绩、修改成绩只使用最新一份已审快照、重置后清空当前公开成员成绩。
