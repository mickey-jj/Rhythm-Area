## 项目具体描述

律竞是一套面向音游赛事主办方的完整网站模板。主办方取得源码及配套文件后，可以选择空白配置或演示预设，在本地完成赛事定义，再运行一个独立的赛事实例。使用同一套模板组织另一场比赛时，应创建新的部署和独立运行数据，不在原网站中新增一张公开赛事卡片。

选手在当前赛事网站中报名、组队、查看赛程、选禁曲和提交成绩；裁判处理审核、比赛判定及获授权的异常事项；观众查看公开规则、名单、对阵和已公布成绩；主办方通过管理后台配置并推进赛事。主办、裁判和选手的权限由后端检查，不依赖前端隐藏按钮。

模板通过有限、可执行的结构化配置适配不同游戏与赛规，不执行用户上传的任意脚本。未实现的选项明确禁用；规则缺失、引用错误或无法执行时，阻止发布并指出原因。

## 使用流程

| 阶段 | 主办方与使用者的操作 | 系统行为 |
| --- | --- | --- |
| 初始化赛事 | 建立管理账号，选择预设或从空白开始，填写赛事信息与规则，导入图池 | 保存草稿，提供校验、规则摘要和流程模拟；未配置完成时不开放普通参赛流程 |
| 发布与运行 | 发布赛事，开放报名，审核资格，组织海选与正赛，处理交分和赛果 | 首页直接展示当前赛事；发布规则与图池快照，持久化进度，按权限与状态执行操作 |
| 结束与归档 | 确认最终结果，关闭普通报名和交分，保留公开赛事记录 | 展示最终成绩、晋级结果和比赛历史；归档不删除审核与判定记录 |
| 复用模板 | 导出规则、图池与可复用展示配置，在新部署中载入 | 建立新的独立赛事，不携带原实例的账号、报名、成绩、会话或私人证据 |

初始化与后续编辑统一由主办方配置入口承载；配置完成后，公众默认看到单场赛事首页，不进入模板选择中心。影响赛程的配置变更使用版本校验，重排未完成赛程，保留已完成比赛及原始规则和曲目。

## 可配置范围（目标）

| 部分 | 具体内容 |
| --- | --- |
| 赛事信息与外观 | 名称、标识、主题色、简介、举办方式、时间及公开联系信息 |
| 游戏与参赛方式 | 游戏名称、客户端版本、难度标签、个人赛或团体赛、参赛容量 |
| 报名与资格 | 报名窗口、审核方式、资格条件、团队人数、成员唯一性与名单冻结 |
| 阶段与晋级 | 海选、单败、双败、循环及阶段之间的资格来源和晋级关系 |
| 图池 | 手工编辑、CSV/JSON 导入、子池、用途、公开时机和版本快照 |
| 选禁曲 | 行动方、动作顺序、数量、候选范围、Ban 作用范围和随机抽曲 |
| 实际演奏顺序 | 独立排列选曲结果，配置固定曲、条件追加曲与加赛曲 |
| 成绩计算 | 指标名称、范围、精度、比较方向、个人与团队聚合及海选取分策略 |
| 同分与异常 | 比较链、加赛、资格附加赛、决赛优势、故障重赛和申诉 |
| 权限与发布 | 主办、裁判和选手权限，报名与成绩审核、赛果确认及公开范围 |

以上为目标能力，不是当前全部可用功能。单赛事定位不取消原规划中的比赛执行能力；团队、复杂赛制与异常处理仍需真正实现和验证后才能启用。

## 页面安排（单赛事目标）

按约 11 个有效业务页面规划，全部服务于当前这一场赛事。该数量是本项目对“网页数量约 10 个”的安排，不是老师要求恰好 11 页。

| 页面 | 目标路由 | 主要用途 |
| --- | --- | --- |
| 赛事首页 | `/` | 当前赛事介绍、阶段进度、公告、报名入口和近期结果 |
| 赛事规则 | `/rules` | 展示由配置生成的完整规则、阶段差异及当前规则版本 |
| 登录注册 | `/auth` | 当前赛事网站内的账号认证 |
| 我的参赛中心 | `/me` | 本人报名、队伍、待办、提交记录和审核结果 |
| 参赛者 | `/participants` | 选手或队伍、冻结名单、种子及资格信息 |
| 赛事图池 | `/pool` | 阶段图池、谱面搜索、难度及用途筛选 |
| 排名赛阶段 | `/schedule/:stageId`（旧 `/qualifier` 自动跳转） | 大倒计时、成绩提交、审核状态和实时排行榜 |
| 赛事看板与阶段 | `/schedule`、`/schedule/:stageId` | 阶段入口、轮次、对阵、轮空和晋级去向；历史赛果独立跳转 |
| 比赛室 | `/matches/:matchId` | 阵容、BP、演奏顺序、比分、加赛和比赛结果 |
| 赛事配置 | `/manage/config` | 初始化与规则编辑、校验、模拟及发布 |
| 赛务后台 | `/manage` | 报名审核、成绩审核、排程、人员、申诉和审计 |

不同场次的比赛室属于同一个页面模板，不重复计数；不同配置生成的示例网站也不用于凑页面数量。关闭某个阶段时，同步隐藏或解释对应入口，避免出现无业务的空页面。

## 技术与数据组织

继续采用 React + TypeScript 前端、Scala 3 后端、Cats Effect IO、PostgreSQL 和 Circe，遵循课程关于纯函数、不可变数据、效果边界和 React 状态组织的要求。报名、交分、审核和比赛进度必须真实经过后端并持久化，不能将完整系统简化为静态配置页。

| 数据类别 | 内容 | 复用边界 |
| --- | --- | --- |
| 模板配置 | 规则、图池结构、主题和文案 | 可导出，在新部署中载入 |
| 当前赛事实例数据 | 账号、报名、冻结名单、BP、成绩、审核、赛果和审计 | 仅属于当前实例，默认不随模板导出 |
| 演示配置与数据 | 范式起源配置、谱面元数据和明确标注的虚构参赛记录 | 可选载入，与正式运行数据区分 |

1. 将默认首页从模板中心改为当前赛事概览，移除公众多赛事大厅、赛事切换和社区式导航。

4. 保留并适配已有规则引擎、图池、交分审核、对阵与事务晋级逻辑。
5. 将范式起源作为可选示例配置与演示数据提供，不作为通用模板必须依赖的正式赛事。
6. 按新的页面安排更新路由、演示流程和验收材料，验证两份独立部署可以使用不同配置且数据互不混用。

## 作业交付与验收目标

最终交付通用模板完整前后端源码、数据库迁移、启动和配置说明、范式起源演示配置、必要验证材料，以及由本人录制的不超过 3 分钟的使用流程视频。源码与视频附件合计按低于 100,000,000 字节并留余量控制；该字节口径是本项目采用的保守预算。

验收重点是：**同一套成果文件能够通过不同配置生成独立的单赛事网站，并真实完成从报名到赛果归档的流程。** 页面数量和前后端协作在单个完整实例内核对，不要求建设社区或同时运营多场赛事。

## 项目根目录一键启动

**双击根目录 Start.cmd**。停止时双击同目录的 **Stop.cmd**，数据保留。入口已包含在源码包根目录，不需要进入 scripts 找命令。

也可在 PowerShell 7 运行 ./scripts/start.ps1 -OpenBrowser。入口准备独立数据库、安装缺失依赖、构建前后端、后台启动、检查 API 与网页健康，并打开浏览器。重复点击已运行的实例时直接打开网页，不重复启动进程。

本期中作业默认网页为 [http://127.0.0.1:5184/](http://127.0.0.1:5184/)，API 为 8092，专用 PostgreSQL 为 55433。进程只绑定本机回环地址。首次使用仍需本机具备 PowerShell 7、Node.js、JDK、sbt launcher 和 PostgreSQL，并联网下载缺失依赖；不把大型运行时或 node_modules 塞入提交包。

如果失败，启动窗口会保留报错。完整日志在 .local/backend.err.log、.local/frontend.err.log 和 .local/postgres.log。不要向聊天或源码包复制数据库密码。
